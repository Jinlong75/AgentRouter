# 任务说明

主导把能写清楚要求的工作写成任务说明，派给执行者：`ar dispatch docs/specs/NNN-简述.md`（默认就带执行者角色，`type: review` 的任务说明默认带审查者角色）。

## 命名

`NNN-简述.md`，至少三位编号递增，`999` 之后继续 `1000`，例如 `001-登录页记住我.md`。

## 每份任务说明包含

1. **目标**：做完后是什么样子（一两句话）。
2. **背景与参照**：相关文件、已有实现、界面稿。
3. **要求**：逐条可检查的要求；不确定的地方写明"留 TODO(lead)"。
4. **允许改动的文件**：路径或通配符。
5. **依赖**（`depends`）：frontmatter 写依赖的说明编号列表；依赖还没合入时 `ar next` 把这些说明列在"等依赖"、不派发。
6. **验收**：要运行的命令（如 `npm test`）和要看的结果。这些命令由门禁跑；验收命令很慢（如完整界面检查）时把 `verify_timeout_min` 写大。
7. **自测**：执行者自己跑哪些与改动相关的测试文件和检查；完整的验收命令不用执行者再跑一遍。
8. **受影响的已有测试**：改行为前先全文搜索依赖旧行为的测试与界面检查，搜索结果不截断、完整贴出，据此写允许改动的文件；没有就写"无"并写出搜过的关键词。

默认项目配置要求代码类说明（code / fix / test / refactor）有 `## 受影响的已有测试` 一节，没有会被拒绝派发；项目可通过 `specRequired` 增加或修改必填章节，填写时查看目标项目配置。

9. **汇报**：按 `docs/roles/worker.md` 的汇报格式。
